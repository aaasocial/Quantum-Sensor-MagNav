# Accessibility audit (A11Y-03)

**Status:** the automated audit passes on the final layout. It finds zero axe violations of any impact, from critical down to minor, in all six states. Every required keyboard target is reachable with Tab. The job and sensor sections open on their own after a Run. The row under the map (jam banner only) stays 56 px high and the position-error box stays 72 px high throughout. The layout checks pass for the two-column arrangement (map alone on the left; Navigation accuracy, Run controls and the collapsed sections on the right) and for the map legend and overlay, which carry the baseline again now that the map follows the UAV zoomed in by default. The Map view radio group is operable from the keyboard. The on-Qollab human walkthrough is recorded below by plan 03-07.

Re-run with `npm --prefix web run audit` (or `cd web && node scripts/audit.mjs`). It rewrites `results/a11y_axe.json`, `results/a11y_keyboard.json` and `docs/hero.png`, and exits 1 on any critical or serious violation, an unreached keyboard target, sections that do not auto-open, a change in the height of the row under the map or of the position-error box, or a layout check failure (see [Layout](#layout-columns-position-error-box-and-map-legend)).

The Vite dev server renders the same React source and aliases `magnav.api` to a stub that returns the real data files and simulates the live-run call sequence (`uav_start`, `uav_quantum`, `live_step`, `live_result`). The real bundle running on Qollab is covered by the human walkthrough below.

**Fixed during this audit.** The first run reported one serious rule, `scrollable-region-focusable`, in every state:
- **Where:** the horizontally scrollable wrappers around the position-error, comparison, benchmark, recorded-seeds and text-alternative tables (3 nodes with sections closed, 6 with them open). The position-error and comparison tables have since moved to the README.
- **Fix:** each wrapper is now a focusable, named region (`web/src/components/TableScroll.jsx`: `role="region"`, `aria-label`, `tabIndex=0`), and the focus ring comes from the existing `:focus-visible` token.
- **Keys:** the page-wide playback keys (Space, arrows, Home, End, J) now skip a focused table region, so those keys scroll the table instead of moving the playhead.

Axe does not check colour contrast inside the map canvas. The canvas is `aria-hidden` and has text alternatives (the figure caption, the legend and the "Map track data" table). The track palette is the colour-blind-safe Phase 2 palette, and every track also differs by dash pattern and marker shape. The map draws the true path, dead reckoning, the classical baseline and the selected quantum track. By default it follows the UAV zoomed in (a window 20 times the mean post-jam baseline-quantum separation, at least 600 m and at most 3000 m across, which is 600 m for both recorded scenarios), so tracks a few tens of metres apart are tens of pixels apart. The baseline is a wide solid orange band with a large triangle, drawn under the quantum dash-dot line and marker: the map matcher often snaps both estimates to the same cell, and there the baseline shows as an orange border around the quantum line. The viewport is set per frame and never animated, so reduced motion needs no separate path. The caption says which view is shown, and the "Map track data" table lists the baseline.

The page has no real-flight link. UI-SPEC A-8 and SCN-03 forbid any link, entry or string for the real-flight project on the page, and a contract test enforces that. Only the README links the published `v0.1.1-smoke` project. The audit records this and would fail if a link appeared that Tab could not reach.

Other keyboard checks:
- On the focused "Sensor" summary, Enter opens the section and Space closes it.
- After the keyboard-started stub Run, both "This Run's IonQ job" and "Sensor" are open (D-02 auto-open).
- The row under the map (D-03, now the jam banner only) is 56 px high when idle, while the Run is in progress, and after the Run with the jam banner showing. The position-error box is 72 px high in the same three states.
- With focus outside any control, Home moves the playhead to the start and the box reads "GPS available"; End moves it to the end and the box shows the error in metres. The box follows the playhead from its new place.

## Layout: columns, position-error box and map legend

Since the 03-07 ad-hoc change (Eason, 2026-10-11) the position-error box is the first item of "Navigation accuracy", above the benchmark, and no longer sits under the map. The row under the map holds only the GPS-jam banner, at a fixed height. The per-track CEP table ("Position error after GPS loss") and the two-scenario comparison ("Both scenarios, as found") are no longer on the page; they are in the README under [Recorded flights after GPS loss](../README.md#recorded-flights-after-gps-loss). The box is not a live region: the single Announcer still speaks the throttled readout during playback, unchanged.

Since the second ad-hoc change (Eason, 2026-10-11), from 900 px the map has the left column to itself, and that column is the wider one (3fr against 2fr; the page may grow to 1440 px, and the map box to 640 px high). The right column holds, top to bottom: one card with "Navigation accuracy" (the position-error box, beside the map) and directly under it the Run controls (map scenario picker with its notes, run mode, the "Run one IonQ job" button and its description, Demo options with the map view, Simulate-a-failure and quantum-track controls, and the playback controls Play, Flight time and Speed; this grouping is from the fourth ad-hoc change); a separate benchmark card (benchmark and recorded-seeds tables, text-alternative tables); the Run status; then the collapsed "This Run's IonQ job" and "Sensor" sections. "What is quantum here" and the footer still span both columns. Below 900 px everything stacks in the same order: map, jam-banner row, Navigation accuracy with the Run controls, benchmark, Run status, job, Sensor. Since the fourth ad-hoc change the map legend lists "Baseline: magnetometer + notch" again and the overlay draws that track and its marker, and Demo options holds the Map view radio group (default "Follow the UAV (zoomed)").

The audit checks this on every viewport, idle and after the Run, and records it under `layout` in `results/a11y_keyboard.json`:
- the box is the first element after the section heading and comes before the benchmark;
- exactly one box is on the page, and none is under the map, whose row contains only the jam slot;
- no table caption starts with "Position error after GPS loss" or "Navigation and signal results for both maps", and no "Both scenarios, as found" heading or comparison block is present;
- the left column contains only the map figure, and the right column's children are, in order, Navigation accuracy, Run controls, Run status, job, Sensor;
- at the wide viewport the page is two columns with the map column the wider, and the error box lies to the right of the map and within its height (at the narrow viewport, one column);
- the map legend lists "Baseline: magnetometer + notch", an overlay stroke uses the baseline colour, and the checked map view is "follow".
