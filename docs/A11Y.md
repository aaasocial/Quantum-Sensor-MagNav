# Accessibility audit (A11Y-03)

**Status:** the automated audit passes on the final layout. It finds zero axe violations of any impact, from critical down to minor, in all six states. Every required keyboard target is reachable with Tab. The job and sensor sections open on their own after a Run. The row under the map (jam banner only) stays 56 px high and the position-error box stays 72 px high throughout. The on-Qollab human walkthrough is recorded below by plan 03-07.

Re-run with `npm --prefix web run audit` (or `cd web && node scripts/audit.mjs`). It rewrites `results/a11y_axe.json`, `results/a11y_keyboard.json` and `docs/hero.png`, and exits 1 on any critical or serious violation, an unreached keyboard target, sections that do not auto-open, a change in the height of the row under the map or of the position-error box, or a layout check failure (see [Layout](#layout-position-error-box-and-readme-only-tables)).

The built `main.js` cannot be audited directly. Its first line is `import * as e from "magnav.api"`, which only Qollab's Pyodide runtime provides, so a plain browser throws. The Vite dev server renders the same React source and aliases `magnav.api` to a stub that returns the real data files and simulates the live-run call sequence (`uav_start`, `uav_quantum`, `live_step`, `live_result`). The real bundle running on Qollab is covered by the human walkthrough below.

Moderate and minor findings: none.

**Fixed during this audit.** The first run reported one serious rule, `scrollable-region-focusable`, in every state:
- **Where:** the horizontally scrollable wrappers around the position-error, comparison, benchmark, recorded-seeds and text-alternative tables (3 nodes with sections closed, 6 with them open). The position-error and comparison tables have since moved to the README.
- **Fix:** each wrapper is now a focusable, named region (`web/src/components/TableScroll.jsx`: `role="region"`, `aria-label`, `tabIndex=0`), and the focus ring comes from the existing `:focus-visible` token.
- **Keys:** the page-wide playback keys (Space, arrows, Home, End, J) now skip a focused table region, so those keys scroll the table instead of moving the playhead.

Axe does not check colour contrast inside the map canvas. The canvas is `aria-hidden` and has text alternatives (the figure caption, the legend and the "Map track data" table). The track palette is the colour-blind-safe Phase 2 palette, and every track also differs by dash pattern and marker shape.

The page has no real-flight link. UI-SPEC A-8 and SCN-03 forbid any link, entry or string for the real-flight project on the page, and a contract test enforces that. Only the README links the published `v0.1.1-smoke` project. The audit records this and would fail if a link appeared that Tab could not reach.

Other keyboard checks:
- On the focused "Sensor" summary, Enter opens the section and Space closes it.
- After the keyboard-started stub Run, both "This Run's IonQ job" and "Sensor" are open (D-02 auto-open).
- The row under the map (D-03, now the jam banner only) is 56 px high when idle, while the Run is in progress, and after the Run with the jam banner showing. The position-error box is 72 px high in the same three states.
- With focus outside any control, Home moves the playhead to the start and the box reads "GPS available"; End moves it to the end and the box shows the error in metres. The box follows the playhead from its new place.

## Layout: position-error box and README-only tables

Since the 03-07 ad-hoc change (Eason, 2026-10-11) the position-error box is the first item of "Navigation accuracy", above the benchmark, and no longer sits under the map. The row under the map holds only the GPS-jam banner, at a fixed height. The per-track CEP table ("Position error after GPS loss") and the two-scenario comparison ("Both scenarios, as found") are no longer on the page; they are in the README under [Recorded flights after GPS loss](../README.md#recorded-flights-after-gps-loss). The box is not a live region: the single Announcer still speaks the throttled readout during playback, unchanged.

The audit checks this on every viewport, idle and after the Run, and records it under `layout` in `results/a11y_keyboard.json`:
- the box is the first element after the section heading and comes before the benchmark;
- exactly one box is on the page, and none is under the map, whose row contains only the jam slot;
- no table caption starts with "Position error after GPS loss" or "Navigation and signal results for both maps", and no "Both scenarios, as found" heading or comparison block is present.
